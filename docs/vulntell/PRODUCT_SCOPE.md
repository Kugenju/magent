# VulnTell MVP 范围与验收

“功能完整”在本项目中定义为：能够稳定完成漏洞情报的采集、规范化、去重、查询、评估和报告，并能在失败或中断后恢复；不等同于覆盖所有漏洞源，也不包含漏洞扫描、利用或攻击验证。

## MVP 必须具备

- 数据源：NVD、CNVD、CISA KEV 至少各有一个可审计适配器；支持 fixture 和显式开启的真实 HTTP 模式；分页、游标、限速、超时、重试和原始响应校验。
- 数据管道：增量同步、断点续跑、重复导入幂等、单条脏数据隔离、跨源 CVE 去重和冲突审计。
- 存储查询：SQLite 可用于本地；生产部署提供 PostgreSQL 适配；按 CVE、来源、严重性、时间窗口和受影响产品检索。
- 评估报告：确定性指标、数据质量告警、来源状态、版本/窗口/数据集元数据；JSON/Markdown 导出；LLM 只能生成解释文本。
- 运行入口：CLI 和可编程 API；任务状态、日志、Trace、Checkpoint 和恢复结果可观测。
- 安全：凭据隔离、SSRF 防护、输入长度限制、Prompt 注入隔离、工具 allowlist、审计日志和数据许可说明。

## 暂不纳入 MVP

实时流处理、分布式调度、多租户 SaaS、自动漏洞扫描/利用、无标注数据的来源排名、默认抓取引用网页、以及必须依赖专有 LLM 的核心逻辑。

## 每个数据源的完成定义

1. 有来源许可、字段映射、限速和失败策略文档；
2. 有离线 fixture、schema/contract 测试和最小真实网络 smoke test（显式开关）；
3. 连续两次增量运行结果一致，重复记录不增长；
4. 在分页中断、429、超时、非法记录和进程重启后可恢复；
5. 原始载荷可通过 hash/ref 追溯，但不会进入默认日志、Trace 或 LLM prompt。

## 交付门槛

当 MVP 的端到端 contract 测试、恢复测试、数据许可审计和安全检查通过后，才考虑 Web 看板或拆分独立仓库。若真实运行暴露的是通用调度/恢复问题，先在 `magent` 增加最小通用能力；若只是领域规则问题，则留在 VulnTell。
